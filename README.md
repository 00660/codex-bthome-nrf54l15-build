# nRF54L15 NTC + 电池 ADC BTHome 固件

面向 `E73-2G4M08S1F / nRF54L15`。**当前走纯 ADC 路线，不碰 IP5328 的 I2C。**

IP5328 那套 I2C 代码全都还在（`src/main.c` 里一点没删），只是用
`IP5328_I2C_ENABLE 0` 关掉了。实测那三根线在这块板子上始终读不通
（详见下面「I2C 为什么放弃了」），所以改成自己分压测电池。

- `P1.10` 只在采样时给 NTC 分压上电
- `P1.11 / AIN4`（模组第 3 脚）采样 NTC 分压点
- `P1.12 / AIN5`（模组第 4 脚）采样电池分压点 —— **电池电压来源**
- `P1.07 / AIN3`（模组第 16 脚）采样充电器输入分压点 —— **插没插充电器**（可选，**默认关**，见 `VBUS_ADC_ENABLE`）
- `P1.13 / AIN6` + `P1.14 / AIN7`（模组 5/6 脚）**差分**测 IP5328 那颗已有采样电阻的压降 —— **电池电流**（可选，见 `SHUNT_ADC_ENABLE`）
- 同时读 SAADC `VDD` 通道，用实际 GPIO 高电平换算 NTC 电阻
- **充电状态**：没有 I2C 就拿不到芯片的充电标志，改看电池电压往哪边走（5 分钟窗口）
- 只读 GATT：报告（16B）、总线诊断（34B，I2C 关掉时整包 `0xFF`）、版本号字符串
- BLE 广播 BTHome v2：temperature、battery、voltage、current、firmware version
- **双唤醒**：每 10 分钟定时醒一次 + 模组第 8 脚按键随时唤醒
- 每轮醒来广播 120 秒（OTA 窗口），之后停止广播进入低功耗睡眠
- **默认常醒测试模式**：不休眠、一直可连接，测完写一个特征切回正常休眠
- MCUboot 双槽升级

## 接线

### NTC

```text
P1.10(GPIO供电) -> 100k固定电阻 -> P1.11/AIN4(ADC) -> 100k NTC -> GND
```

### 电池电压分压（必接，电池电压的唯一来源）

```text
BAT ──[R1 1MΩ]──┬────────── 模组第 4 脚 (P1.12 / AIN5)
                │
                ├──||──────── 100nF ────┐
                │                        │
                └──[R2 1MΩ]──────────────┴──── GND
```

- **绝对不要把 4.2V 电池直接怼到模组引脚上**，必须分压。
- **别用 100k**。100k+100k 会白耗 21µA，可能比充电宝自己的待机电流还大，
  而且常开着会把电池慢慢放空。用 **1M + 1M（约 2.1µA）**。
  更省可以用 **4.7M + 4.7M（约 0.45µA）**，但要等约 1.2 秒（5τ）读数才稳，
  固件那 5 秒采样间隔够用。
- **必须加 100nF**。1MΩ 的输出阻抗对 SAADC 太高，采样瞬间会把这点的电压拉塌，
  读数会乱跳。100nF 接在**分压中点**（= 模组第 4 脚那根线）和 GND 之间，
  也就是**和 R2 并联**。电容无极性，耐压 ≥ 6.3V 即可。

默认按 1:1 分压算（`R1 = R2`），满电 4.2V → 2.1V，离 SAADC 的 3.6V 满量程
（内部 0.9V 参考 × 1/4 增益）还有余量。
换别的阻值只改 `src/main.c` 里的 `BAT_ADC_DIVIDER_NUM / _DEN`。

**分压没接时读数会被丢掉**：AIN5 悬空时 ADC 会读到乱七八糟的值，
所以固件只在换算回 BAT 端后落进 `1.5V ~ 5.0V` 才认，否则当成"没接"。

### 充电器输入 VBUS（可选，默认关）

```text
充电器输入 VBUS ──[1MΩ]──┬────────── 模组第 16 脚 (P1.07 / AIN3)
                          │
                          ├──||──── 100nF ────┐
                          │                   │
                          └──[150kΩ]──────────┴──── GND
```

分压比约 7.67:1：5V → 0.65V，9V → 1.17V，12V → 1.56V，20V → 2.61V，
全部落在 SAADC 的 3.6V 满量程内。分压后超过 250mV（≈ 输入 1.9V）就认为插着充电器。

⚠️ **`VBUS_ADC_ENABLE` 默认是 `0`** —— 这一脚现在**悬空**，什么都没接。
悬空脚的 ADC 读数会乱飘（实测报到 `3335mV`，按 7.67:1 反推输入端是 25.6V，
根本不可能），会被当成"插着充电器"，纯属误导。

**接上分压之后，把 `src/main.c` 里的 `VBUS_ADC_ENABLE` 改成 `1`** 才会启用。
不接也能用：充电状态仍然可以靠电池电压斜率判断（慢一些）。

### 电池电流（差分 ADC，可选）

**采样电阻不用自己加** —— 板子上已经有了，就是 IP5328 的 **24 脚 VSP / 25 脚 VSN**
之间那颗（IP5328 自己内部 14bit ADC 在读的那颗）。不用割线、不用串新电阻。

要加的是**两路分压**，共 4 颗 1M：

```text
         ┌──────── 采样电阻（板上已有）────────┐
         │                                    │
     VSP(24)                              VSN(25)
         │                                    │
      [1M]                                 [1M]
         ├──→ 模组 5 脚 (P1.13/AIN6)          ├──→ 模组 6 脚 (P1.14/AIN7)
         │      正输入                        │      负输入
      [1M]                                 [1M]
         │                                    │
        GND                                  GND
         │                                    │
     ── 100nF ──                          ── 100nF ──
```

**模组 5/6 脚原来接 IP5328 I2C 的那两根线要拆掉**，这两脚现在改成电流采样用。

- **为什么必须分压**：VSP/VSN 坐在 VSYS 上（3.0~4.2V），直接进 ADC 脚会超过模组
  VDD(3.3V) 的绝对最大额定值。分压后共模降到 1.5~2.1V，安全。
- **为什么用 1M 而不是 100k**：误差主要来自两颗电阻的**失配**（1% 失配 → 约 21mV
  固定偏置），跟阻值绝对值无关；而 1M 的静态电流只有 2.1µA/路（两条腿共 4.2µA），
  不毁待机。100k 会白耗 42µA。
- **两颗 1M 要配对**（1% 或更好），否则那个固定偏置会盖过真实信号。
- 通道用 `GAIN_4`（满量程 ±0.225V，约 0.11mV/LSB），采样电阻 10mΩ、2A 时约 91 个码。

#### 标定（必做，因为手册没给采样电阻阻值）

1. 让设备**空载**（不充电、不带负载），读报告包 `[12:14]` 的差分 mV，
   把它填进 `src/main.c` 的 `SHUNT_OFFSET_MV`。
2. 挂一个**已知电流**的负载，读 `[12:14]`（单位 mV，已还原到采样电阻两端），
   真实阻值 = `差分mV ÷ 电流(A)`，填进 `SHUNT_MILLIOHM`。
3. 填完 `[14:16]` 的 mA 就准了。

`SHUNT_ADC_ENABLE` 置 0 就不采样，报告里 `[12:16]` 恒为 0。

### IP5328 的 I2C（已停用）

> **这一节现在只是留档。** 三根线（模组 5/6/7 脚）已经拆掉了，
> 固件里 `IP5328_I2C_ENABLE` 也是 `0`。哪天要捡回来再看下面。

| 信号 | IP5328 侧 | E73 模组脚 | nRF54L15 | 说明 |
|---|---|---|---|---|
| I2C SCL | **DMB = 6 脚** | **5** | P1.13 | I2C 模式 2 的 SCK，接线顺序写死 |
| I2C SDA | **DPB = 7 脚** | **6** | P1.14 | I2C 模式 2 的 SDA |
| INT/RSET | **RSET = 21 脚** | **7** | P1.04 | 输入，主板醒着为高 |
| KEY | **KEY = 26 脚** | **8** | P1.02 | 按键网络，下降沿唤醒 MCU（NFC1）；固件也能主动拉低当按键用。**固件给这一脚开了内部上拉**，原因见下 |

⚠️ **别焊到 5 脚！** 手册第 3 页引脚说明：

```text
4  DMC   USB C 口手机快充智能识别DM
5  DPC   USB C 口手机快充智能识别DP     ← 不是 I2C 脚！
6  DMB   Micro USB 口手机快充智能识别DM，I2C2 功能时为 SCK   ← SCL
7  DPB   Micro USB 口手机快充智能识别DP，I2C2 功能时为 SDA   ← SDA
```

**IP5328 侧的 I2C 模式 2 是 6 / 7 两脚，不是 5 / 6。** 5 脚是 Type-C 口的 DP 快充识别脚，
焊上去既读不到数据，还会干扰 Type-C 快充握手（插着充电器时两边互相顶电流，
模组可能被拉得不启动）。

⚠️ **IP5328 有两套 I2C 引脚，别接错那一套**（手册第 19 页）：

| | SCK | SDA | 唤醒 / INT | 代价 |
|---|---|---|---|---|
| **I2C 模式 2** | **DMB(6)** | **DPB(7)** | **RSET(21)** | 失去 USB 口手机快充识别（DM/DP） ✅ 本方案 |
| I2C 模式 1 | L1(11) | L2(12) | L3(13) | 失去电量显示灯；且 L3 复用 VSET，**绝对不能接 MCU** |

**两种模式 IP5328 都是从机，从机地址都是 `0xEA`/`0xEB`**，区别只在用哪组引脚。
不管接哪一组，芯片都会「自动关闭 Function 功能，自动进入 IIC 模式」。

⚠️ **模式 1 的 L3(13) 千万别接 MCU**：它是充电恒压设定脚（复用 VSET），
接单片机引脚会把终止电压顶高，4.2V 电池有过充起火风险。
模式 1 的 L1/L2 上还挂着电量灯 LED，LED 阳极接 VREG、阴极接 L1/L2，
等效一个把线钳在约 2V 的负载，低于 nRF54L15 的判决门限，得把 3.3k 上拉一起挪过去。

⚠️ **芯片待机时不响应 I2C**。手册第 20 页：「在 I2C 模式下，IP5328P 关机时 RSET 为
低电平，开机时为高电平」。所以读之前要先把升压叫起来。固件在 `0x75` 不应答时会
**主动把模组第 8 脚拉低 150ms**（等于替用户按一下充电宝的键）再重试。

- I2C 两根线各用 `3.3k`（手册值，`4.7k` 也能用）上拉到 IP5328 的 `VREG`(3.1V)，
  **不能上拉到 VDD 或 3.3V**。VREG 是常开 LDO，负载能力 30mA。
- 第 8 脚是 `P1.02 = NFC1`，复位后默认是 NFC 天线脚。overlay 里已经用
  `&uicr { nfct-pins-as-gpios; };` 关掉 NFC，不用改硬件。
- 第 13 脚（`P1.03 = NFC2`）配成高阻不驱动。两个 NFC 脚被驱动到不同电平会有额外漏电流。

#### I2C 为什么放弃了

实测 0.19.0 / 0.20.0 / 0.21.0 三个版本，诊断包逐字节完全一样：

```text
[1] INT/RSET = 低
SCL/SDA: 高阻=高 内部上拉=高 内部下拉=高 释放恢复=高   ← 有强外部上拉，线是通的
[10][11][12] 2µs/20µs/100µs probe 0x75 = 1（NAK）
[13..16] 全地址扫描 0x08~0x77 → 0 命中
[19][20] 静默 1 秒总线跳变 = 0/0      ← 线上没有别的主机
[21] 按键后 probe = 1（NAK）
[30] 反向组合(6=SCL,5=SDA) probe = 1（NAK）  [31] 反向扫描 0 命中
[32] 长按 10 秒复位 IP5328 后 probe = 1（NAK）  [33] 复位后扫描 0 命中
```

**关键一条**：按键能被芯片响应（`[22]` 变高）= Function 功能还开着 =
**芯片从来没进 I2C 模式**。进模式的唯一条件是「上电那一刻 DMB/DPB 为高」，
所以 3.3k 上拉必须挂在 IP5328 自己的 `VREG(27)` 上。长按 10 秒复位也救不回来，
进一步钉死这个结论。

固件侧能做的全做完了（正反组合、三级速率、全地址扫描、按键唤醒、复位重检测），
线上始终没有任何从机应答。剩下的只能在硬件侧查（量 27 脚是否 3.1V、上拉是不是挂在
27 脚上、5/6 脚到芯片 6/7 脚之间有没有串未装的电阻）。**暂时不查了，改走 ADC。**

#### 焊接注意（焊完不启动时按这个顺序查）

1. **先确认共地**。模组的 `GND` 必须和 IP5328 的 `GND` 直接连通。如果模组是单独供电
   （USB 串口、另一个电源）而地没连起来，I2C 线一接上，电流就会从模组引脚经 ESD 二极管
   倒灌进模组的 VDD 域，表现就是"焊上就不启动"。**这种情况必须把两地接在一起再焊信号线。**
2. **确认焊的是 DMB(6) / DPB(7)，不是 5 脚、也不是 L1(11) / L2(12)**。5 脚是 Type-C 的 DPC；
   L1/L2 属于 I2C 模式 1，和模式 2 互斥。焊错脚探测必然全 NAK。
3. **每根信号线串一颗 100Ω ~ 1kΩ 电阻**。限流后即使引脚焊错或短路，也不会把
   模组或 IP5328 拉死。这是最省事的一道保险。
4. **上拉要装在 IP5328 侧、拉到 VREG**，而且要保证 IP5328 上电那一刻就已经在位。
   上拉装反到 VDD/3.3V 或者没装，芯片上电检测不到高电平，就不会进 I2C 模式。
5. 焊完先**只接 GND 和两根信号线，不接上拉**，上电看模组是否正常广播；
   确认没问题再加 3.3k 上拉，再上电看一次。分步验证，出问题立刻能定位。

## 唤醒与 OTA 窗口

```text
上电 ──────────► 采样 → 广播 120 秒 → 停止广播 → 睡
每 10 分钟 ────► 采样 → 广播 120 秒 → 停止广播 → 睡
第 8 脚按下 ───► 采样 → 广播 120 秒 → 停止广播 → 睡
```

- 两种唤醒走同一套流程。定时唤醒用 `k_sem_take(&wake_sem, K_MINUTES(10))` 的超时实现，
  按键唤醒由 `P1.02` 的下降沿中断 `k_sem_give()` 提前打断，所以一个等待点同时覆盖两种来源。
- **广播期间始终可连接**。OTA 客户端就是"一直轮询扫描 + 撞上窗口就连"，
  所以任何一个窗口都必须允许连接，不能只在某个特定窗口才可连。
- 连上之后不会睡：`advertise_then_stop()` 里会一直等到连接断开才停止广播。
- 上电后第一轮也走同样流程，保证刷完固件还能连上验证或重刷。

### 第 8 脚（KEY）必须开内部上拉

手册从头到尾没说 KEY 有内部上拉，图 3 的接法是：

```text
KEY ──[R]──[按键]── GND
KEY ── WLED(照明 LED，阳极在 KEY、阴极在 GND)
```

那个 WLED LED 会把 KEY 钳在约 1.8V，**低于 nRF54L15 在 3.1V 供电下的判决门限
（约 2.17V）**。如果按之前那样把 `P1.02` 配成纯高阻输入，不按键和按下都读成低，
下降沿永远不来，第 8 脚唤醒等于没接。

所以 `configure_key_wakeup()` 给这一脚开了 `GPIO_PULL_UP`。
（ESP32-C3 那边同样是必须开内部上拉才能唤醒，现象一致。）

诊断字节 `[24]` 就是拿来验这一点的：读回 `1` = 上拉能压过 KEY 网络的负载，
按键唤醒可用；读回 `0` = KEY 网络被 LED 或下拉钳死，得上 100k 外部上拉。

**端到端验证**：诊断字节 `[0]` 的 bit5 标着"本次诊断是按键唤醒触发的"。
上电那次的诊断是 `0`；**按一下充电宝的实体键**，固件会重跑一次诊断，
这时候 bit5 变成 `1` —— 说明下降沿中断真的来了，第 8 脚唤醒通了。

代价：nRF 内部上拉约 13k，静止时白耗 ~240µA。量产在意这个数的话，
可以在 KEY 网络对 3.1V 挂一颗 100k 外部上拉，再把这里改回纯高阻。

## BLE 广播

设备名放在 scan response 里（广播包 31 字节放不下完整名字 + 18 字节 service data）。

BTHome service data（18 字节）：

```text
D2 FC 40 01 BB 02 TT TT 0C VV VV 5D CC CC F2 PP MM JJ
```

| 字节 | 内容 |
|---|---|
| `D2 FC` | BTHome UUID，小端 |
| `40` | BTHome v2，未加密 |
| `01 BB` | battery，uint8，单位 % |
| `02 TT TT` | temperature，sint16，factor 0.01 °C |
| `0C VV VV` | voltage，uint16，factor 0.001 V（IP5328 的 BATOCV 开路电压） |
| `5D CC CC` | current (signed)，sint16，factor 0.001 A，充电为正、放电为负 |
| `F2 PP MM JJ` | firmware version，patch / minor / major |

⚠️ **BTHome 要求 object id 按数值从小到大排列**，接收端碰到不认识的 id 会直接停止解析后面的内容。
所以顺序必须是 `01 < 02 < 0C < 5D < F2`，改字段时别打乱。

⚠️ 电流用的是 **`0x5D`（signed current）**，不是 `0x43`。`0x43` 是无符号版本，
电池放电时会因为负数被解释成很大的正数。

电量百分比：有 IP5328 数据时用 BATOCV 查放电曲线表算；没有时用 ADC 实测的电池电压查同一张表；
连电池分压都没接时，才回退到原来的 VDD 电压法。

电流：有 IP5328 数据时用它报的 `BATIAD`；没有时用模组 5/6 脚的差分 ADC 测出来的值
（见上面「电池电流」）。

## GATT 报告

除了广播，还挂了一个只读特征值 `6F6B0201-8C9A-4CC4-A848-16B7E44F5415`（16 字节，小端）。

`[0]` 是**包类型**，决定后面怎么读：

| `[0]` | 含义 |
|---|---|
| **`0xFE`** | **纯 ADC 包**（当前默认）。I2C 关着或不响应，整包内容见下表 |
| `0x00` | I2C 不通，且模组 4 脚分压也没接（整包全 0） |
| `0x01` / `0x02` | I2C 通了，低 2 bit 是引脚组合，内容走 IP5328 寄存器 |

### `[0] = 0xFE`（纯 ADC 包，当前固件默认）

| 偏移 | 内容 |
|---|---|
| `[1]` | bit0~2 充电状态（同 `[2]`），bit4 充电中，bit6 已充满 —— 沿用原位的位语义，方便旧解析器 |
| `[2]` | 充电状态低 3 bit：`0` UNKNOWN / `1` IDLE / `2` CHARGING / `3` DISCHARGING / `4` FULL |
| `[3]` | 电量 % |
| `[4:6]` | 电池电压 mV（**分压已换算回 BAT 端**） |
| `[6:8]` | 分压后、换算前的原始 mV（1:1 分压时约等于电池电压的一半） |
| `[8:10]` | 充电器输入 VBUS 分压后的 mV，`0` = 没插 / 这一路关着（`VBUS_ADC_ENABLE = 0`） |
| `[10:12]` | 充电状态（和 `[1]` bit0~2、`[2]` 同值，方便只读两字节的人） |
| `[12:14]` | 电池电流差分值换算回**采样电阻两端**的 mV（signed） |
| `[14:16]` | 电池电流 mA（signed，按 `SHUNT_MILLIOHM` 换算，未标定前仅供参考） |

### `[0] = 0x01 / 0x02`（IP5328 寄存器包，I2C 打开时才有）

| 偏移 | 内容 |
|---|---|
| `[0]` | `0x01`/`0x02` = I2C 通了，低 2 bit 是引脚组合 |
| `[1]` | bit0~2 系统状态，bit4 充电中，bit6 已充满 |
| `[2]` | bit0~2 充电阶段（0 IDLE / 1 涓流 / 2 恒流 / 3 恒压 / 4 停充检测 / 5 充满 / 6 超时） |
| `[3]` | 电量 % |
| `[4:6]` | BATOCV 开路电压 mV |
| `[6:8]` | BATVAD 端电压 mV |
| `[8:10]` | BATIAD 电池电流 mA（有符号） |
| `[10:12]` | VSYS 电压 mV |
| `[12:14]` | VSYS 电流 mA（有符号） |
| `[14:16]` | 功率 mW |

寄存器来源与换算：

| 寄存器 | 内容 | 换算 |
|---|---|---|
| 0xD1 | 系统状态 / 充电 / 充满 | 见上表 |
| 0xD7 | 充电阶段 | 见上表 |
| 0x7B:0x7A | BATOCV | mV = raw × 0.26855 + 2600 |
| 0x65:0x64 | BAT 端电压 | mV = raw × 0.26855 + 2600 |
| 0x67:0x66 | BAT 端电流 | mA = raw × 1.27883，补码，充正放负 |
| 0x69:0x68 | VSYS 电压 | mV = raw × 1.61133 + 15600 |
| 0x6B:0x6A | VSYS 电流 | mA = raw × 0.6394 |
| 0x7D:0x7C | 功率 | mW = raw × 8.44 |

从机地址写 `0xEA` / 读 `0xEB`（7bit = `0x75`），地址小端（低字节地址在前）。

## 充电状态怎么来的（没有 I2C 时）

读不到 IP5328 的充电标志，只能看**电池电压往哪边走**：

| 现象 | 判断 |
|---|---|
| 窗口平均值涨了 ≥ 5mV | `CHARGING` 充电中 |
| 窗口平均值跌了 ≥ 5mV | `DISCHARGING` 放电中 |
| 基本不动，且平均值 ≥ 4.10V | `FULL` 已充满 |
| 基本不动，且平均值 < 4.10V | `IDLE` 待机 |

**为什么是"窗口平均值比窗口平均值"，而不是两个单点相减**：
实测电池读数在 `4124 ~ 4140 mV` 之间跳，**峰峰值 16mV（±8mV）**。
用单点比单点、阈值 8mV 的话，噪声自己就能把阈值顶穿 ——
0.23.0 实测就是这个毛病：电池明明平着没充，却报了 `CHARGING`。

改成窗口内所有采样点累加、到点取平均再相减，5 分钟按 5 秒一次能攒 60 个点，
噪声从 ±6mV 压到 ±0.8mV 左右，阈值就能降到 5mV 而不被噪声误触发。

**为什么窗口是 5 分钟**：锂电池在 3.7~4.0V 那段曲线很平，恒流充电时电压每分钟
只涨 1~2mV，5 分钟真实涨 5~10mV。窗口再短就分不出来，阈值再低又会被噪声淹掉。

**第一个窗口只用来打基准**（这时候状态是 `0` UNKNOWN），所以开机后要满**两个**
窗口才出第一个判断：常醒测试模式约 10 分钟，正常 10 分钟周期则是两轮。

⚠️ **电池接近满的时候，这个方法天然不可靠**：进入恒压阶段后电压被钉在 4.2V，
斜率几乎为 0，充不充电都看不出来。**要可靠地判断"插没插充电器"，
只能把模组第 16 脚的 VBUS 分压接上**（见上），那是直接的数字信号。

接上之后，插没插充电器可以直接从报告包的 `[8:10]` 读出来。

## I2C 总线诊断（I2C 关掉时整包 `0xFF`）

同一个服务下还有第二个只读特征值 `6F6B0202-8C9A-4CC4-A848-16B7E44F5415`（34 字节）。

**当前固件 `IP5328_I2C_ENABLE = 0`，这个特征值整包填 `0xFF`**，表示"没跑过诊断"。
下面这张表是 I2C 打开时才有意义的，留着备用。

打开 I2C 时，读不通不用示波器，看它就能定位卡在哪一步。
每轮采样前重跑一次，所以**按一下充电宝的键**就能拿到一份最新快照。

接线顺序是**定死**的：模组 5 脚（P1.13）= SCL，6 脚（P1.14）= SDA，
固件不再去试反向组合。

| 偏移 | 内容 |
|---|---|
| `[0]` | bit0 已跑过，bit1 2µs 收到 ACK，bit2 20µs 收到 ACK，bit3 100µs 收到 ACK，bit4 总线恢复后 SDA 仍被拉低，**bit5 本次诊断是第 8 脚按键唤醒触发的** |
| `[1]` | INT/RSET（P1.04）电平，`1` = 主板醒着 |
| `[2]` `[3]` | SCL / SDA 纯高阻电平 |
| `[4]` `[5]` | SCL / SDA 内部上拉电平 |
| `[6]` `[7]` | SCL / SDA 内部下拉电平 |
| `[8]` `[9]` | SCL / SDA 驱动到低再放开后的电平，`1` = **确实有外部上拉** |
| `[10]` | **2µs** 下 probe `0x75`，`0` = ACK |
| `[11]` | **20µs** 下 probe `0x75`，`0` = ACK |
| `[12]` | **100µs** 下 probe `0x75`，`0` = ACK |
| `[13]` `[14]` | 快速全地址扫描命中个数 / 首个命中地址（7bit） |
| `[15]` `[16]` | 慢速（100µs）全地址扫描命中个数 / 首个命中地址 |
| `[17]` | INT（P1.04）纯高阻时的电平 |
| `[18]` | INT（P1.04）**加内部上拉**时的电平 |
| `[19]` `[20]` | 按键**之前**，静默**约 1 秒**内 SCL / SDA 自己跳变了几次（饱和 255） |
| `[21]` | 按键**之后** probe `0x75`，`0` = ACK，`0xFF` = 没测 |
| `[22]` | 按键**之后** INT（P1.04）加内部上拉时的电平 |
| `[23]` | 按键**之后**快速全地址扫描命中个数 |
| `[24]` | 按键放开 50ms 后第 8 脚的电平，`1` = KEY 网络上确实有上拉（这根线接对了） |
| `[25]` `[26]` | 第 8 脚：驱动低放开 / 驱动高放开 1ms 后的电平 |
| `[27]` `[28]` | 第 7 脚（INT）：同上 |
| `[29]` | 第 13 脚（NFC2，本该悬空）：驱动低放开后的电平 |
| `[30]` | 反向组合（6 脚 = SCL、5 脚 = SDA）2µs 下 probe `0x75`，`0` = ACK |
| `[31]` | 反向组合全地址扫描命中个数 |
| `[32]` | **长按 KEY 10 秒复位 IP5328 之后**，probe `0x75`，`0` = ACK |
| `[33]` | 复位之后快速全地址扫描命中个数 |

`[32]`/`[33]` 是最后手段。手册第 18 页：**「超长按 10s 可复位整个系统」**。
芯片只在**自己上电那一刻**检测 DMB/DPB 电平来决定进不进 I2C 模式，一旦错过就再也进不去；
而长按复位是唯一不用拔电池就能让它重跑一遍这个检测的软件办法。
诊断跑到最后会自己按一次（前面先隔 1.2s，免得被算成"1s 内两次短按"而关机）。

> ⚠️ 如果模组本身也从 IP5328 的 VREG 取电，这一下会把自己也一起重启。
> 没关系，重启后固件会重新跑一遍诊断。

`[30]`/`[31]` **只报结果，不参与主流程** —— 主流程一律按 5=SCL / 6=SDA 走。
加这两格是因为：主板上的 I2C 口常常是从 USB 口的 DM/DP 引出来的，而
**USB 的 DM/DP 和 IP5328 的 SCL/SDA 是交叉的**（手册第 3 页：DMB = 快充识别 DM
兼 I2C2 的 SCK，DPB = 快充识别 DP 兼 SDA）。照着 USB 丝印接，很容易反过来。

`[25]`~`[29]` 是把"没上拉"和"悬空"分开用的。单看"驱动低放开读低"分不出
"这根线接了对地电阻"和"这根线什么都没接"；再驱动到高放开一次，等 1ms，
悬空的脚靠引脚电容撑住还是高，接了对地阻抗的已经泄到低：

```text
低 / 高  → 悬空，这根线什么都没接
高 / 高  → 接在一个有上拉的网络上
低 / 低  → 接在对地阻抗上（一颗电阻，或者对端在推低）
```

每次 probe 之前都会先做一次**总线恢复**（9 个时钟 + STOP），
把卡在半个字节里、正拉着 SDA 不放的从机踢出来。
哪个速率能通就自动固定用哪个速率。

固件会在**开机第一轮**和**按键唤醒时**跑一遍诊断。更重要的：如果 `0x75`
不应答，固件会**主动把模组第 8 脚拉低 150ms**（等于替用户按一下充电宝的键），
把 IP5328 从待机叫起来再试一次。手册第 20 页写着「I2C 模式下 IP5328P
关机时 RSET 为低电平，开机时为高电平」—— 待机时整颗芯片都可能不响应 I2C。

判读方法（**仅 I2C 打开时有意义**）：

```text
[32] = 0 或 [33] != 0 → 长按复位之后通了！芯片之前就是上电那一刻没检测到
                        DMB/DPB 为高才没进 I2C 模式，复位让它重跑检测就进去了。
[30] = 0 或 [31] != 0 → 两根线接反了！反向组合能通。对调模组 5 / 6 即可。
                        主板 I2C 口常从 USB 的 DM/DP 引出，而 USB 的 DM/DP 和
                        IP5328 的 SCL/SDA 是交叉的（DMB=DM 兼 SCK，DPB=DP 兼 SDA）。
[25]/[26] = 低/高      → 第 8 脚悬空，根本没接在 KEY 网络上。先查这根线，
                        其它结论都不成立。
[19] 或 [20] 不为 0   → 这两个脚上另有主机在跑 I2C。
                        接错到了 IP5328 的 I2C1（L1/L2/L3，它自己当主机的口），
                        两个主机互相不理。要从机口：DMB(6)=SCL、DPB(7)=SDA、RSET(21)=INT。
[21] = 0              → 按一下键就通了。芯片平时在待机，固件已能自己唤醒。
[8]/[9] 都是 0        → 线没上拉 / 没焊好 / 根本没接上
[0] bit4 = 1          → 从机把 SDA 拉死了，接线可能有短路
[10] = 0              → 2µs 就通了
[11] = 0              → 20µs 才通，固件已自动切到该速率
[12] = 0              → 100µs 才通，固件已自动切到该速率
[13]/[15] 有命中      → 从机地址不是 0x75
[18] 或 [22] = 1 但都不通 → 芯片已经进了 I2C 模式（INT 在推高），
                        但线没接在 DMB/DPB 上
全部不通且 [18]=[22]=0 → 有上拉、没从机、线上也没有别的活动。
                        手册说按对应方式连接会【自动】进 I2C 模式并应答 0xEA，
                        既然没进，最可能就是这两根线不在 DMB(6) / DPB(7) 上。
                        用万用表通断档量：模组 5 脚 ↔ IP5328 第 6 脚、
                        模组 6 脚 ↔ IP5328 第 7 脚。
```

## 版本号

只读特征值 `6F6B0301-8C9A-4CC4-A848-16B7E44F5415`（ASCII 字符串，如 `0.10.0`），
挂在服务 `6F6B0300-…` 下。和广播里的 BTHome `0xF2` 对象同源（都来自 `VERSION` 文件），
两处不会不一致。

## 常醒测试模式

同一服务下的 `6F6B0302-8C9A-4CC4-A848-16B7E44F5415`（可读可写，1 字节）：

| 值 | 行为 |
|---|---|
| `0` | **常醒**：广播不收，一直可连接；数据每 5 秒刷一次，按键也能立刻刷 |
| `1` | 正常休眠：每 10 分钟醒一轮，广播 120 秒后睡 |

**默认是 `0` 常醒**（`STAY_AWAKE_DEFAULT = 1`）。功能测试期间不用等 10 分钟窗口，
随时都能连上去看数据。测完往这个特征写 `1` 就切回正常休眠，不用重新刷机。

量产前把 `src/main.c` 里的 `STAY_AWAKE_DEFAULT` 改成 `0`，让设备默认就省电。

⚠️ 常醒模式会一直开着射频，电流是毫安级，长时间挂机会把充电宝电量耗掉，
测完记得切回 `1`。

## 软件 I2C 的接线顺序（已停用）

> `IP5328_I2C_ENABLE = 0` 时下面这套完全不生效，留档。

**写死，不自动判定**：

```text
模组 5 脚（P1.13）= SCL
模组 6 脚（P1.14）= SDA
```

早期版本启动时会把两个组合都试一遍（`5=SCL/6=SDA` 和反过来的 `6=SCL/5=SDA`）。
现在只 bind 这一个组合 —— 一是接线顺序已经确定，二是每多探一次就往总线上多打一轮
时钟，反而可能搅掉 IP5328 那边的模式判定。

GATT 报告的 `[0]` 字节仍然会带 `bind` 值（`1` = 已绑定），日志里也会打印 `bind=`。

⚠️ IP5328 是在**上电启动时**检测引脚电平来决定进不进 I2C 模式的。
如果一直读不到，把电池断开再重新接上（让它重新启动检测），或者插一次充电器。
I2C 打开时固件为了不打扰这个过程，开机后有 **30 秒安静期**，期间完全不碰这两根线。
**I2C 关掉时没有这个静默期，开机立刻开始采样。**

## GPIO 测试开关

原来的 27 路 GPIO 测试服务保留，但移除了被 IP5328 占用的 5 个脚：

```text
P1.02（模组 8 脚，KEY）
P1.03（NFC2，跟随 P1.02 电平）
P1.04（模组 7 脚，INT）
P1.13 / P1.14（模组 5/6 脚，I2C）
```

剩余 22 路。**其余引脚的 UUID 编号保持不变**，手机端原来的配置不会错位。

I2C 关掉之后 `P1.13 / P1.14 / P1.04` 在 `configure_ip5328_io()` 里被配成**纯高阻输入**
（不驱动、不加上拉），免得拆掉线之后悬空脚互相漏电。

## OTA

固件是"醒来才广播"的，所以 OTA 客户端要一直轮询扫描，撞上窗口就连：

```text
每轮窗口：120 秒可连接广播
窗口之间：停止广播，低功耗睡眠
```

用 Python `smpclient` 升级：

```powershell
smpclient --ble-address EA:9F:FE:F3:26:5B --img artifacts\bthome_nrf54l15_app.signed.bin
```

如果扫不到，先按一下设备上的按键（第 8 脚 KEY 网络），设备会立刻开一个 120 秒的窗口。
或者等下一个 10 分钟定时窗口。
